## 一、系统概览

### 1.1 职责

- **gov-bot**：KN Chat 交互守护进程。长轮询 `getUpdates` 实时接收用户消息，自动识别命令/问题，处理并回复。
- **gov_profiler**：表画像查询模块。给定表名返回延迟/停更/调用者等数据治理画像。
- **gov_llm**：Qwen 模型调用模块。把画像数据组织成自然语言回答（参考 n8n「异常sql优化通知」模型调用）。

### 1.2 技术栈

| 组件 | 技术 |
|---|---|
| 语言 | Python 3.8+（纯标准库，无第三方依赖） |
| 机器人 | KN Chat Bot API（兼容 Telegram Bot API） |
| 长轮询 | `getUpdates?timeout=30`（挂起等消息，实时） |
| 模型 | Qwen3.7-plus（DashScope 国际版，OpenAI 兼容） |
| 存储 | 本地 JSON（测试）→ MySQL 台账（生产） |
| 部署 | systemd / nohup（服务器常驻） |

## 三、模型调用（正式上线依据）

### 3.1 模型配置来源

模型调用方式**完全参考 n8n 工作流「异常sql优化通知」（QAfXbbb5Ej6Cg6Bu）的 `Call Qwen Chat API` 节点**：

| 参数 | 值 |
|---|---|
| API | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1/chat/completions` |
| 模型 | `qwen3.7-plus` |
| 认证 | `Authorization: Bearer <token>`（OpenAI 兼容） |
| 格式 | POST JSON `{model, messages, stream:false}` |

### 3.2 调用代码（gov_llm.py）

```python
from gov_llm import ask_qwen

answer = ask_qwen(
    user_prompt="查一下 ods_app_hold_apply 是不是僵尸表",
    system_prompt="你是数据治理专家，负责数仓僵尸表识别、数据质量、血缘分析。回答用简洁中文，结合给定的数据事实，不要编造数据。"
)
```

### 3.3 环境变量（生产必须，勿硬编码）

| 变量 | 说明 | 生产值 |
|---|---|---|
| `QWEN_URL` | DashScope 地址 | 同上 |
| `QWEN_API_KEY` | API Key | 从 n8n 工作流拷贝/或申请专属 key |
| `QWEN_MODEL` | 模型名 | `qwen3.7-plus` |
| `KN_CHAT_BOT_TOKEN` | KN Chat bot token | **专属「数据治理专家」bot token**（正式） |
| `RECORD_GROUP_CHAT_ID` | 记录群 chat_id | 记录群 |
| `GOV_DATA_DIR` | 画像数据目录 | `/opt/gov-bot/data` |

### 3.4 为什么用 Qwen3.7-plus

- 与 n8n「异常sql优化通知」生产工作流**同一模型**，经验证稳定
- 已实测：`qwen3.7-plus` 能正确理解画像数据、组织结构化回答、给出治理建议
- DashScope 国际版无需内网，公网服务器可访问

## 四、交互流程

### 4.1 消息分类

```
收到消息
  ├─ /命令 → 直接处理（保留/下线/归档/不在我/help/my）
  └─ 自由文本 → 提取表名 → 查画像 → Qwen 组织回答
```

### 4.2 自由问题回答链路

```
用户: "查一下 ods_app_hold_apply 是不是僵尸表"
  ↓ extract_table_from_question() → "ods_app_hold_apply"
  ↓ profile_table() → 画像 dict（延迟668天/源库停更/调用者u_qilonghuang）
  ↓ format_profile() → 结构化摘要
  ↓ ask_qwen(画像摘要 + 用户问题) → Qwen 回答
  ↓ sendMessage → 用户收到
  ↓ 记录群转发 + 台账落库
```

### 4.3 画像数据源

| 数据 | 文件 | 说明 |
|---|---|---|
| 延迟名单 | `th-delay-list.json` | 表名/最新时间/延迟天数/级别 |
| 源库对照 | `th-final-catalog.json` | 源库MAX vs odsMAX（停更判定） |
| 调用者 | `th-owners-full.json` | 真实调用者/次数/最近时间 |
| ods配置 | `th-ods-tables.json` | 增量字段/源表（可选） |

> 生产：这些快照应由 Pi 包定时扫描刷新，写入 `GOV_DATA_DIR`。

### 5.2 部署步骤

```bash
# 1. 拷贝代码
scp -r gov-bot/ root@server:/opt/gov-bot

# 2. 配置环境变量
cat > /opt/gov-bot/.env <<'EOF'
KN_CHAT_BOT_TOKEN=专属bot_token
RECORD_GROUP_CHAT_ID=记录群chat_id
QWEN_API_KEY=sk-xxx
QWEN_MODEL=qwen3.7-plus
GOV_DATA_DIR=/opt/gov-bot/data
EOF

# 3. systemd 常驻
sudo tee /etc/systemd/system/gov-bot.service > /dev/null <<'EOF'
[Unit]
Description=Data Governance Bot (KN Chat)
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/gov-bot
ExecStart=/usr/bin/python3 /opt/gov-bot/gov-bot.py
EnvironmentFile=/opt/gov-bot/.env
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload && sudo systemctl enable --now gov-bot
journalctl -u gov-bot -f
```

## 六、安全与边界

| 项 | 要求 |
|---|---|
| DROP | 只生成草稿，不自动执行 |
| 查询 | 只读查询，不写生产数据 |
| Token | 生产走环境变量，不硬编码 |
| 单实例 | 同一 bot 只能一个守护进程（getUpdates 独占） |
| 用户白名单 | 测试阶段仅 jiangchuanchen；生产放开真实负责人 |
| 系统账号 | 过滤 `e\_%`、root/admin/backup_user、biz_ 服务账号 |

## 七、与 Pi 包 / ZNZB 的关系

| 组件 | 职责 | 端口 |
|---|---|---|
